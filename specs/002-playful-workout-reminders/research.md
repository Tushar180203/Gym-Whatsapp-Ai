# Research decisions

- Decision: Use normal messages within the existing 24-hour window; optionally use approved WhatsApp templates outside it, with one body parameter containing a deterministic plan summary. Rationale: proactive reminders can fall outside the 24-hour user-initiated window. Template sending does not itself reopen free-form messaging. Sources: [Meta SDK template reference](https://whatsapp.github.io/WhatsApp-Nodejs-SDK/api-reference/messages/template/) and [Meta SDK session quickstart](https://whatsapp.github.io/WhatsApp-Nodejs-SDK/). The user explicitly selected an initial version without template approval; in-window reminders are supported, while closed-window reminders are skipped.
- Decision: Use existing PostgreSQL outbound intents and unique notification keys. Rationale: preserve owner locking, correlation and cautious unknown-outcome handling. Alternative: in-process timers with direct sends; rejected because restarts can lose or repeat messages.
- Decision: Explicit reminder opt-in in the profile, with saved time zone and routine weekdays. Rationale: no silent enrollment or arbitrary training-day selection. Alternative: enable all linked users; rejected because existing workout consent is not a reminder preference.
- Decision: Poll every 30 seconds with 10-minute catch-up and 05:15 expiry. Rationale: tolerate brief restarts without sending obsolete reminders late in the day.
- External configuration: the approved template name/language is not available in repository source. Runtime skips closed-window reminders until configured; open-window reminders work immediately after deployment. The documented copy remains ready for later Meta submission. No product design questions remain unresolved.
